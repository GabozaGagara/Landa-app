# LANDA — финансовый учёт и поставщики

LANDA — веб-приложение для просчёта, кассы, поставщиков, накладных и контроля финансовых операций.

## Приложения

- `index.html` — основной административный интерфейс.
- `supplier.html` — кабинет поставщика: отправка накладной, свои накладные и баланс.
- `cloudflare/worker.mjs` — защищённый поставщицкий API. Работает с приватным GitHub JSON.
- `cloudflare/supplier-view.mjs` — read-only фильтрация данных по поставщику.
- `js/landa-control-center.js` — контроль накладных, журнал, акты сверки и аналитика продаж.
- `js/landa-local-backups.js` — независимые локальные версии IndexedDB.

## Ключевые правила

1. **Публичный репозиторий содержит только код.** Финансовые данные хранятся в отдельном приватном репозитории. Секреты `GH_TOKEN` и `SUPPLIER_CODES` должны быть только в Cloudflare Runtime Secrets.
2. **Долг поставщику не равен стоимости всех накладных.** Только начисленные накладные влияют на баланс. Неначисленные поставки отображаются отдельно.
3. **Новые накладные поставщика требуют подтверждения владельцем.** Только после проверки стоимости, состава и доставки можно начислить долг.
4. **СДЭК не проверяется автоматически через официальный API.** Программа хранит статусы LANDA и поддерживает ручные/пакетные подтверждения; не интерпретируйте их как live tracking.
5. **Аналитические продажи не проводят деньги по кассе.** Когда продажи будут интегрированы в учёт, понадобится отдельное подтверждение проводок.
6. **Принудительная облачная запись блокируется**, если GitHub JSON изменился после последней известной версии. При конфликте сначала сохраните локальную полную JSON-копию.
7. **Локальные резервные версии IndexedDB не заменяют внешнюю резервную копию.** Полный JSON нужно хранить отдельно от браузера.

## Автоматическая синхронизация между устройствами

При включённой автосинхронизации и рабочем токене приватного GitHub LANDA передаёт:

- финансовый просчёт (строки, периоды, суммы, история), накладные, цены, статусы, поставщиков, платежи, зачёты, кассу, валютные операции и продажи — через `landa-data/backup.json`;
- расходы, сверку приёмки, объединения товаров, связи с «МойСклад» и журналы смешанных паллет — через `landa-data/auxiliary-sync.json`.

Изменения в разных записях объединяются автоматически, включая добавление товаров в один открытый журнал паллеты. Если оба устройства по-разному изменили **одну и ту же** сумму, удалили редактируемую запись или закрыли паллету во время чужой погрузки, программа останавливает объединение с предупреждением, не выбирая произвольно одну из версий. Синхронизация возможна только при интернет-соединении и доступе к приватному репозиторию; это не гарантия мгновенного обновления.

Токены GitHub, коды доступа и настройки подключения сервисов остаются только на устройстве — передавать их через финансовые JSON-файлы небезопасно. На каждом устройстве нужно один раз подключить GitHub и включить автоматическую синхронизацию.

## Проверки

На каждое изменение `main` и PR действует Workflow
`/.github/workflows/landa-checks.yml`.

Без внешних библиотек (Node.js 22):

```bash
node tests/validate-source.mjs
node --check cloudflare/worker.mjs
node --check js/landa-control-center.js
```

Проверяется целостность HTML, синтаксис встроенных скриптов, наличие защищённого API и модель расчётов по поставщикам на синтетических данных. Перед публикацией финансовых изменений также необходимы браузерные интеграционные тесты и проверка резервной копии.

## Переход на D1

`cloudflare/migrations/0001_landa_finance_schema.sql` и
`docs/D1_MIGRATION.md` — **только подготовка**.

**Рабочая база пока не D1.** Нельзя применять удалённую миграцию или включать D1 в production Worker, пока не готовы проверенный импорт, роль администратора, сопоставление всех остатков и откат.

## Обновление

Приложение публикуется через GitHub Pages. Не вставляйте в `index.html` приватный JSON, токены GitHub, коды поставщиков или другие секреты. После изменения Cloudflare Worker проверьте успешную сборку и реальные сценарии на тестовой накладной без изменения финансовых итогов.
