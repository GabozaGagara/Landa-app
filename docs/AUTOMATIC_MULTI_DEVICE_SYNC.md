# LANDA — автоматическая синхронизация всех рабочих журналов

## Что теперь синхронизируется

Все данные владельца, для которых уже есть стандартный способ хранения в LANDA:

| Данные | Приватный файл GitHub |
|---|---|
| Финансовый просчёт, периоды, счета, касса, накладные, оплаты, поставщики, их статусы | Существующий \`landa-data/backup.json\` |
| Вкладка **«Расходы»** — суммы, даты и описания, включая прежние валюты | Новый \`landa-data/auxiliary-sync.json\` |
| Ручная сверка товаров и комментарии | Новый \`auxiliary-sync.json\` |
| Ручные объединения похожих наименований | Новый \`auxiliary-sync.json\` |
| Ручные соответствия товаров «МойСклад» | Новый \`auxiliary-sync.json\` |
| Журнал погрузки/приёмки смешанного паллета СДЭК | Новый \`auxiliary-sync.json\` |

**Никаких расходов в финансовую кассу не добавляется.** Второй файл только синхронизирует ранее независимые журналы. Сервер Cloudflare продолжает писать новые накладные от поставщиков в существующий финансовый файл; дополнительных секретов в публичном репозитории нет.

Не синхронизируются сознательно: токены, коды доступа владельца и поставщиков, резервные технические копии браузера, настройки конкретного устройства и незаполненные черновики формы. Это секреты или локальные настройки, а не рабочие данные.

## Как включить на каждом устройстве

1. Откройте **https://gabozagagara.github.io/Landa-app/** по HTTPS и перезагрузите страницу (Ctrl+Shift+R).
2. Выберите **«☁ Синхронизация GitHub»** в боковом меню.
3. Укажите **приватный** репозиторий \`GabozaGagara/Landa-financenot\` и путь к основной базе \`landa-data/backup.json\`. Используйте существующий fine-grained токен GitHub, разрешение **Contents: Read & write только для приватного репозитория**.
4. Включите **«Автоматическая синхронизация»**, затем нажмите **«Подключить и проверить»**. На личном устройстве можно отметить **«Запомнить токен»**, чтобы синхронизация продолжалась после перезапуска браузера. **Не запоминайте токен на чужом устройстве.**
5. Посмотрите статус под заголовком **«Дополнительные данные»**. Существующие локальные расходы будут объединены с теми, что уже лежат в облаке, по уникальным ID; недостающие записи загрузятся на устройство.

На втором устройстве подключите **тот же приватный репозиторий** и один раз авторизуйте его. Далее загрузка и отправка проходят автоматически: при входе в приложение, после изменений и периодически во время работы. Интернет необходим; при сбое записи остаются локально и повторно проверяются позже.

**Нельзя безопасно синхронизировать личные финансы на новом устройстве совсем без авторизации:** для этого пришлось бы опубликовать общий токен доступа к приватным данным. LANDA этого не делает.

## Механизм защиты от потери данных

- Основная база использует существующий контроль SHA при записи GitHub. Когда облако изменилось, а локальная версия не редактировалась, LANDA автоматически загружает новые финансы и накладные. Если и облако, и локальная версия изменились несовместимым образом, программа **останавливает запись и показывает конфликт**.
- Дополнительные журналы синхронизируются отдельно, по принципу *трёхстороннего сравнения* — предыдущая подтверждённая версия, локальные правки и облачные правки. Разные новые расходы/позиции объединяются; удаление существующей записи учитывается, если другой пользователь её не изменил. При разных изменениях **одной и той же записи** система останавливается и ничего не затирает.
- Невозможно случайно объединить одну товарную позицию в две разные группы, а исчезновение локального журнала после прежней синхронизации не считается разрешением массово удалить облачные данные.
- Если при загрузке дополнительных данных локальный журнал меняется, операция откладывается. При получении обновлений интерфейс перезагружается после сохранения данных и только когда нет открытых форм/диалогов. Несохранённый ввод не должен заменяться фоновым обновлением.
- Перед отправкой доп. данных приложение проверяет, что репозиторий GitHub **приватный**. Автоматический журнал не содержит GH-токенов и не меняет \`backup.json\`.
- История коммитов GitHub позволяет восстановить предыдущий JSON при серьёзной ошибке. Отдельные JSON-выгрузки расходов/паллета рекомендуются как дополнительный резервный вариант.

## Ограничения

- Это **автоматическая синхронизация с периодическими проверками**, не мгновенный общий онлайн-редактор. Обычно новая запись становится доступной через несколько десятков секунд после успешного сохранения.
- Одновременное редактирование одной финансовой записи или одной и той же карточки приёмки на разных устройствах может потребовать ручного разрешения конфликта. Это лучше, чем потеря учёта.
- Данные в GitHub доступны владельцам токенов/доступа к приватному репозиторию, **не зашифрованы сквозным шифрованием**.
- Во время первой настройки на уже используемом устройстве, где и облако, и локальная финансовая база отличаются, LANDA может запросить ручной выбор исходной финансовой версии. Это защита от перезаписи старых расчётов и накладных.
- GitHub имеет технические лимиты на частоту запросов и размер файла. При их достижении приложение покажет ошибку, а данные останутся локально.

## Файлы и проверка

- \`js/landa-aux-sync-core.mjs\`: чистая проверка структуры и безопасное слияние по ID, без токенов.
- \`js/landa-aux-sync.mjs\`: привязка к тому же приватному GitHub с отдельным файлом \`landa-data/auxiliary-sync.json\`.
- \`tests/aux-sync.test.mjs\`: тесты независимых записей, одновременных правок, удаления, дублей, объединений и отката частичной записи.
- \`index.html\`: существующая финансовая синхронизация продолжает работать независимо; интервал проверки сокращён до ~30 секунд, добавлен статус доп. данных.
- Для этих изменений **не требуется новый деплой Cloudflare Worker**, но требуется обновить GitHub Pages и на каждом устройстве один раз подключить репозиторий.

**Финансовая база владельца не открывалась, не читалась и не изменялась при внесении этих изменений в публичный код.** Синхронизация читает/записывает её только в браузере, после авторизации самим владельцем.
