# LANDA · «Финансовый просчёт» B · Безопасное внедрение

**Статус:** интерфейс опубликован в исходном коде; не объявлять проверенным на рабочей базе до отдельного подтверждения пользователя. Финансовый резервный файл `GabozaGagara/Landa-financenot:landa-data/backup.json` не читается и не меняется этим внедрением.

## Этап 0 — исходная структура и инварианты

Текущий исходный финансовый формат: `proschet.version=1`, список `groups`, `snapshots`, `rows`; каждая строка имеет собственный `id`, `name`, `group`, `subgroup`, `values` по `snapshot.id`, факультативные `notes`, `sourceRow` и `aux`. Контрольные значения хранятся в `controlTotals`. Раздел `extras` **не включается** в основной финансовый итог. Пустое значение отличается от явно записанного нуля; отрицательные суммы не превращаются в положительные.

Публичный исходный шаблон в `index.html` содержит шесть групп и один пустой начальный период; **рабочие исторические суммы находятся вне публичного репозитория**. Поэтому точные количества реальных строк, периодов и сверка с реальными суммами здесь не объявляются выполненными.

Чистые функции и регрессионные тесты: `js/landa-proschet-b-core.mjs`, `tests/proschet-b.test.mjs`. Они тестируют искусственный набор, не загружая частные финансовые записи: суммы всех групп и дат, исключение `extras`, знаки, хронологию сравнений, дубли, архив, отсутствие мутаций, обнаружение повреждения исторических значений.

Формальная проверка на полной *локальной копии* перед вводом в работу должна сравнить **каждую строку и её поля, порядок, `groups`, `snapshots`, `controlTotals`, общий итог и итоги групп каждой даты**, а не только общую текущую сумму. Не использовать live `backup.json` в CI.

## Изменения интерфейса

Новый `js/landa-proschet-b.mjs` подключён к `index.html`, не заменяя старые математические функции:
- **Кратко** — сводные группы и раскрываемые подгруппы; просмотр исходных строк.
- **Подробно** — тот же исходный список со звёздочками, проверками, примечаниями и визуальным архивом.
- **Изменения** — позиции с наибольшим изменением относительно прошлой даты и подсказки о повторяющихся названиях.
- **Классический** — прежний вид без новых элементов.
- **Быстрая проверка** — статус привязан к ID строки, ID даты и конкретному значению (если число поменялось, статус «проверено» автоматически пропадает).
- **Избранное, комментарии, архив** — только в `localStorage` этого браузера, ключ `landa_proschet_b_prefs_v1`.

**Важные ограничения:** архив пока **только скрывает строку**, не исключает её суммы из прошлого или текущего итога. «Возможные дубли» — предложения на основе совпадающего нормализованного названия внутри группы; **автоматического объединения или исключения сумм нет**. Новые комментарии хранятся отдельно от старых `row.notes`. Отметки и настройки пока **не синхронизируются между устройствами** и не входят в GitHub JSON. При очистке данных сайта они исчезнут; финансовая история при этом остаётся отдельной.

## Безопасная проверка перед расширением

1. Запустить `node --test tests/landa.test.mjs tests/proschet-b.test.mjs`, `node --check js/landa-proschet-b-core.mjs`, `node --check js/landa-proschet-b.mjs`.
2. На копии рабочего набора открыть **Классический** режим и зафиксировать итог всех дат и групп.
3. Открыть **Кратко** → раскрыть и закрыть подгруппы → убедиться в равенстве итогов.
4. На отдельной тестовой строке поставить «Проверено», затем изменить число и убедиться, что отметка устарела. **Не делать это в рабочей базе.**
5. Проверить избранное, комментарий и архив на искусственных строках. Убедиться, что значения и экспорт прежние, а историческая дата видна.
6. Проверить поиск и фильтры, переключение режимов, мобильный экран и защиту от конфликтов GitHub в двух браузерах.
7. Только после подтверждения этапа проверки рассматривать синхронизацию метаданных между устройствами и реальные изменения структуры.

## План возврата

При некорректной работе нового вида переключиться на **Классический**. Если ошибку вызывает новый JS-модуль, убрать только его строку `<script type="module" src="./js/landa-proschet-b.mjs"></script>` из публичного `index.html`; данные пользователя не нужно восстанавливать из резервной копии, поскольку модуль не меняет финансовый объект. До любых других изменений сохранить полную пользовательскую JSON-копию.

**Важно:** отдельный слой интерфейса не делает автономную локальную копию единственным источником истины. Действующие правила синхронизации финансовой базы GitHub и обнаружения конфликтов остаются прежними.
