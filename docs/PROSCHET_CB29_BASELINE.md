# LANDA — новая основа просчёта от 29.10.2026

## Что реализовано в интерфейсе

1. **Новый расчёт** создаёт новый `snapshot` с пустыми значениями всех исходных строк. Строки и их последовательность **не изменяются**. После создания включается фильтр **«Все»**, поэтому незаполненные позиции остаются видимыми.
2. Под последней группой размещены два ручных поля **«Доход, ₽ (+)»** и **«Расход, ₽ (−)»**; они привязаны к ID даты и хранятся внутри `proschet.periodAdjustments`. Для старых дат, где поля отсутствуют, оба значения считаются равными нулю. Старые финансовые строки не мигрируют и не меняются.
3. Финальный итог периода рассчитывается как **сумма учитываемых строк + доход − расход**. Отличие от предыдущего просчёта сравнивает именно два финальных итога. Пока не заполнены все учитываемые строки, показано предупреждение «предварительно».
4. Встроенная сверка с Excel `controlTotals[snapshotId]` по-прежнему сравнивает **только сумму исходных строк** без дополнительных дохода и расхода. CSV экспортирует сумму строк, доход, расход, скорректированный итог и отклонение от предыдущего периода.
5. График истории общего итога использует скорректированный итог каждой даты. Поля дохода и расхода **не связаны** с кассой, поставщиками, накладными или отдельной вкладкой «Расходы».

## Как получить данные из Google Sheets

**Фактические CB1:CB289 пока не были доступны при разработке.** Google Drive для чата необходимо подключить либо предоставить экспорт Google Sheets. До получения источника **не существует проверенного числа основы**. Не импортируйте выдуманные суммы.

Прямо в программе предусмотрен альтернативный ручной импорт:

1. Откройте Google Sheets → лист «просчет». Выделите ровно `CB1:CB289` и скопируйте.
2. Откройте LANDA → «Финансовый просчёт» → **«Основа 29.10 · CB»**.
3. Вставьте содержимое одного столбца, нажмите **«Проверить данные»**.
4. Программа проверит количество ячеек (289), числа `CB1:CB288`, контроль `CB289` и связь каждой заполненной строки с номером источника `sourceRow` в LANDA. Заголовки листа в первых четырёх строках игнорируются.
5. Если ранее в LANDA не было структуры исходных строк с номером строки или сумма не совпадает, **импорт блокируется**. Нужно импортировать исходную структуру листа с названиями строк, а не угадывать группировку.
6. При совпадении и явном подтверждении будет создан **отдельный** период «29.10.2026 · Основа CB». История и исходный порядок останутся нетронутыми. База GitHub обновляется через обычный механизм синхронизации пользователя, а не редактируется этой функцией напрямую.

Импорт заблокирован, если в текущей финансовой базе уже есть период с датой 29.10.2026; данные другого периода не заменяются. Проверка суммы использует существующее правило LANDA: группа `extras` не входит в общий итог. Если фактическая формула `CB289` учитывает другую область, до изменения правил необходимо сверить исходный лист.

**Важное ограничение:** диапазон `CB1:CB289` содержит значения одной даты, но не гарантирует наличие названий и принадлежности строк к разделам. Программа не создаёт вымышленные названия. Для исходной структуры потребуется сам лист Google Sheets или его экспорт с названиями.

## Финансовая безопасность

Исходный приватный GitHub `GabozaGagara/Landa-financenot` и `landa-data/backup.json` **не менялись разработчиком**. Все изменения были в публичном коде интерфейса и тестах. Перед фактическим импортом рекомендуется сделать полную резервную копию данных и убедиться, что текущая GitHub-синхронизация показывает актуальную облачную версию.

Проверки: `node --test tests/proschet-period.test.mjs`. Используются только искусственные цифры.
