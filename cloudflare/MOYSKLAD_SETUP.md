# LANDA — подключение приёмок «МойСклад» (только чтение)

## 1. Подготовка

1. Создайте персональный API-токен «МойСклад» с доступом к чтению приёмок и каталога товаров. По возможности используйте сотрудника с правами **только на просмотр**.
2. В Cloudflare → Workers & Pages → **landa-app** → Settings → Variables and Secrets → **Production** добавьте два зашифрованных секрета:
   - `MOYSKLAD_TOKEN` — API-токен «МойСклад».
   - `LANDA_MS_ADMIN_KEY` — **новый отдельный случайный пароль не короче 32 символов**, не совпадающий с личными кодами поставщиков и GitHub-токеном.
3. Не размещайте токены или пароли в GitHub, URL, HTML и переписке.
4. После обновления Cloudflare Worker проверьте статус Deployment → Ready. Изменение кода в GitHub **не гарантирует**, что Worker уже развёрнут.

## 2. Работа

1. Откройте https://gabozagagara.github.io/Landa-app/ и загрузите актуальную облачную копию LANDA штатным способом.
2. Откройте боковой раздел **«Приёмка · МойСклад»**.
3. Выберите поставщика LANDA и даты **приёмок в «МоёмСкладе»** (максимум 32 дня за один запрос).
4. Введите отдельный код владельца (секрет `LANDA_MS_ADMIN_KEY`, его не нужно передавать помощнику).
5. Нажмите **«Загрузить приёмки»**. Программа получит только проведённые документы `supply` и их позиции.
6. Отметьте вручённые накладные LANDA и конкретные документы приёмки, которые следует сопоставить.
7. Сверьте предложенные соответствия товаров. Одинаковые уникальные артикулы и названия предлагаются автоматически. При разночтениях или нескольких вариантах выберите точный товар вручную и подтвердите.
8. Нажмите **«Сверить выбранное»**, проверьте расхождения и скачайте CSV.

## Защита от неверной сверки

- Не сравнивайте все приёмки за период со всеми вручёнными накладными автоматически. Выбирайте связанные документы.
- Статус «Вручен» в LANDA — **текущий учётный статус**, а не доказательство вручения на историческую дату.
- Положительная разница означает: в выбранных приёмках больше единиц, чем заявлено в выбранных накладных.
- Если несколько разных названий LANDA связаны с одним товаром «МоегоСклада», программа выдаёт **общую разницу**, не распределяя её между строками произвольно.
- Сопоставления сохраняются отдельно в локальном хранилище браузера. Это **не** синхронизация между устройствами; очищение браузера удалит их.
- API-токен «МойСклад» остаётся на стороне Cloudflare. Код владельца вводится для каждого открытия панели и не сохраняется.
- Запросы к МойСклад используют **только GET**. `landa-data/backup.json`, касса, задолженность, складские остатки и документы «МоегоСклада» **не изменяются**.

## Диагностика

- 403 «Неверный код владельца»: проверьте `LANDA_MS_ADMIN_KEY` в Production secrets.
- 503 «не настроен»: проверьте оба секрета и статус рабочего deployment.
- 404: Worker не обновлён / развёрнут устаревший код.
- 502: токен «МойСклад» недействителен либо недостаточно прав чтения, API недоступен или вернул ошибку.
- «В текущих данных LANDA нет вручённых накладных»: проверьте актуальность синхронизации и статусы документов.
- Если программа сообщает о неполной приёмке, уменьшите период и повторите загрузку. Неполные данные нельзя считать полноценной сверкой.
