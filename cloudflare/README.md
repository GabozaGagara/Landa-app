# LANDA · Приём накладных от поставщиков

Серверная часть для **автоматической передачи накладных** от Анны, Алины и Анатолия в приватный GitHub-репозиторий LANDA. Без сервиса 17TRACK.

Статус: исходный код готов; реальная передача заработает **после** подключения Cloudflare Worker и настройки секретов владельцем. Публичный GitHub Pages сайт не умеет хранить приватный GitHub-токен.

## Установить из GitHub через Cloudflare (подходит без терминала)

1. Войдите в [Cloudflare](https://dash.cloudflare.com/), откройте **Workers & Pages → Create application → GitHub**. Разрешите Cloudflare доступ к *публичному* репозиторию `GabozaGagara/Landa-app`, выберите его.
2. Настройте **Worker name:** `landa-supplier-bridge`, **Root directory:** `cloudflare`, **Production branch:** `main`, **Deploy command:** `npx wrangler deploy`; сборка не требуется. Нажмите **Save and Deploy**.
3. На странице Worker откройте **Settings → Variables and Secrets → Add**. Создайте две переменные **типа Secret**, а не Text:
   - `GH_TOKEN`: **отдельный новый** fine-grained GitHub PAT владельца, с доступом **только** к `GabozaGagara/Landa-financenot` и правом **Contents: Read and write**. Не используйте токен доступа к публичному репозиторию.
   - `SUPPLIER_CODES`: JSON из трёх независимых случайных секретных кодов длиной не меньше 24 символов каждый, например `{"anna":"<сильный-код-Анны>","alina":"<сильный-код-Алины>","anatoly":"<сильный-код-Анатолия>"}`. **Тексты-заглушки не являются кодами.** Коды генерируйте в менеджере паролей; отправляйте каждому поставщику только его код.
4. Нажмите **Deploy** для применения секретов.
5. Откройте адрес вида `https://landa-supplier-bridge.<ваш-subdomain>.workers.dev/health`. Должен появиться JSON с полем `"app":"LANDA-supplier-bridge"` и `"github":true`. Это лишь наличие GitHub-токена, **не** подтверждение его прав: доступ к базе проверяется при пробной отправке.
6. В своей [LANDA](https://gabozagagara.github.io/Landa-app/?v=17) откройте **Накладные → Кабинеты поставщиков**. Вставьте адрес `https://...workers.dev/` в поле сервера, нажмите **Сохранить адрес → Проверить связь**, затем скопируйте три ссылки.
7. Передайте поставщикам соответствующие ссылки и персональные коды отдельно. После успешной отправки накладная **сразу** появляется в приватном `landa-data/backup.json`; владелец нажимает **Синхронизация GitHub → Проверить облако** для загрузки изменений в браузер LANDA.

## Безопасность и ограничения

- **Никогда** не помещайте GitHub PAT или `SUPPLIER_CODES` в этот репозиторий, в HTML, сообщения чата или в поле "адрес Worker". Разрешения токена ограничьте только одной приватной базой.
- Поставщик имеет право добавить накладную с кодом **своего поставщика**. Он не читает базу и не может менять кассу, платежи, взаиморасчёты или финансовый просчёт. Программа проверяет дубликаты номера.
- Автоматический импорт принимает **отправления из Бреста**, но **не** проверяет их статус в СДЭК. Начальный статус — `Создан`, начисление долга отключено. Реальные статусы проверяются отдельно по официальному сайту СДЭК и через кнопку пакетной проверки / Work в LANDA.
- Проверка `/health` публична и сообщает только наличие токена, а не сам токен. Проверять `/health` **не надо** с секретными кодами.
- CORS и Origin ограничивают браузерную интеграцию, но не служат авторизацией; авторизация обеспечивается длинными персональными кодами. При подозрении на утечку код или токен нужно заменить.
- Если редактируете Worker прямо в Cloudflare и подключаете автоматические GitHub-сборки, следующая сборка из `main` может перезаписать ручные правки кода. Секреты хранятся отдельно от исходного кода.

Документация Cloudflare: [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/), [конфигурация сборки](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/), [секреты](https://developers.cloudflare.com/workers/configuration/secrets/).
